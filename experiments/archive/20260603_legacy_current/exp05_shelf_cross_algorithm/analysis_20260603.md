# Exp05 Shelf Cross-Algorithm Analysis

Current artifact:

`outputs/new_experiments/exp05_shelf_cross_algorithm_split_s3_20260603/`

Partial confirmation artifact:

`outputs/new_experiments/exp05_shelf_cross_algorithm_split_s8_20260603/`

Protocol:

- Shelf+IIWA combined scene, five fixed query pairs.
- Three random seeds, so aggregate task count is 15 audited queries.
- SBF row uses the optimized Exp.4 leaf-refine baseline:
  `leaf8->14 + deep box200/d28 + read-only d23 external evidence`.
- PRM, BIT*, and RRTConnect are run in separate subprocesses to avoid the old
  combined OMPL runner hanging one method behind another.
- Audit time is not counted in SBF planning time.
- IRIS-NP+GCS is run as a separate one-seed reduced diagnostic using the local
  conda `sbf` Python and `gcs-science-robotics` checkout.

## Interpretation

The updated SBF baseline is much faster than PRM/BIT* under the current strict
audit aggregate, and it succeeds on all 15 shelf queries. RRTConnect is also
fast and succeeds on all 15 queries, with substantially shorter paths. Therefore
Exp.5 does not support a broad claim that SBF dominates RRTConnect as a one-shot
query planner. The defensible claim is narrower and stronger: SBF builds an
explicit audited box-region graph with very low segment fallback, while OMPL
single-query planners can be faster or shorter when region reuse is not valued.

## Implementation Findings

1. The old combined OMPL invocation was not a reliable dispatcher: PRM, BIT*,
   and RRTConnect are now split into separate child artifacts.
2. The SBF Exp.5 row now calls `run_leaf_refine_tradeoff.py` directly, keeping
   the shelf cross-algorithm baseline aligned with Exp.4.
3. IRIS-NP+GCS requires a non-default Python environment. The dispatcher now
   preflights the selected `--iris-python` and `--iris-gcs-repo` and records
   skipped dependencies if unavailable. On this machine the local conda `sbf`
   environment and `/home/tian/桌面/box_aabb/gcs-science-robotics` checkout make
   the reduced diagnostic executable.
