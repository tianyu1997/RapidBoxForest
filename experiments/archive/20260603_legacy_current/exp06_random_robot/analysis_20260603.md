## Interpretation

This reduced run verifies that the random-scene SBF pipeline now executes across
all three robots and difficulties and passes strict audit. It does not support a
runtime advantage over RRTConnect in these randomly sampled one-shot queries:
IRIS-NP+GCS, PRM, BIT*, and RRTConnect all succeed on all 9 tasks with lower
charged time. The SBF staged pipeline is therefore best kept as a generalization
and cache-mechanism stress test, not as the primary evidence for fast Shelf+IIWA
leaf-refine planning.

The current data are consistent with the paper's narrower claim that RBF can
construct audited region graphs across different robot kinematics. They do not
support a broad claim that staged SBF dominates single-query sampling planners
on random scenes.

## Implementation Findings

1. `run_random_robot.py` needed `REPO_ROOT.parent` on `sys.path` so subprocesses
   can import `RapidBoxForest`.
2. The p18 random cache validator now checks split-policy and schedule hashes;
   stale caches with incompatible LECT semantics are deleted and rebuilt.
3. `paper_15_random_anytime_tradeoff.py` now maps the public
   `support_hull_coverage` label to the lifelong p18 preset so evaluation and
   prewarm caches use compatible split semantics.
4. `QueryResult.path_as_lists()` was added to the Python binding so strict audit
   paths can be read without requiring `numpy`.

## Remaining Scope

This is not the full Exp.6 final matrix. A full paper-facing random-scene run
would still need five scene seeds. The reduced all-method slice is sufficient to
show that random one-shot queries do not support a staged-SBF runtime dominance
claim.
